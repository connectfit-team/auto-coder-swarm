# 정확도를 올리는 법 — 다음 사람에게

이 저장소에는 자동으로 코드를 쓰는 것이 둘 있다.

| | 무엇 | 재는 것 |
|---|---|---|
| **손 (ACS)** | 우리 저장소를 고친다 | `~/tally.py` — 계약 자식이 승인 대기에 닿는 비율 |
| **에이전트** | 도구를 쥐고 조사한다 | `agent -eval` — 답을 아는 물음의 정답률 |

둘 다 **재고 나서 고친다.** 이 글은 그 방법과, 이미 재 본 것들이다.

## 1. 재는 법

### 손 (ACS)

    ssh cnf@office
    bash ~/acs.sh busy          # IDLE 인지 본다. 도는 작업 위에 배포하면 그게 죽는다
    bash ~/deploy.sh acs        # master 를 배포한다
    RUNS=12 bash ~/after2.sh    # 12판 돌린다 (한 판 10~20분)
    python3 ~/tally.py 20       # 분류한다

`tally.py` 는 승인 대기 비율, **실패를 마지막으로 막은 관문**, 그 까닭, 그리고
도구를 쥔 고치기(#226)가 몇 번 돌아 몇 번 도움이 됐는지를 낸다.

**한 판이 10~20분이다.** 이 기계는 05:00·13:00·21:00 에 재부팅하므로, 12판을
돌리려면 재부팅 직후에 시작한다.

### 에이전트

    LLM_DIRECT_URL=http://localhost:8000 \
      ./bin/agent -config ~/.acs/mcp.json -eval eval/rea-binary.json -repeat 2

    ./bin/agent -config ~/.acs/mcp.json -verify   # 도구·절차·지침을 다 받는지 (LLM 안 씀)

물음의 답은 **다른 연장으로 뽑아 확인한다**(`nm -D`·`file`·`strings`).
지어낸 답으로 재면 재는 쪽이 틀린다.

## 2. 지킬 것 — 전부 어겨 보고 적은 것이다

1. **표본이 작으면 잡음을 쫓는 것이다.** 물음 넷으로 고치다 3/4 → 0/4 → 3/4 를
   왕복했다. 한 문항이 25%인 크기에서는 가를 수 없다. **12 이상**으로 한다.
2. **문항마다 본다**(`-repeat`). 늘 맞는 것과 늘 틀리는 것만 고칠 거리다.
   왔다 갔다 하는 것을 고치려 들면 잡음을 쫓는 것이다.
3. **돌려 보고 고친다.** 단위시험은 **가짜 서버**를 쓴다 — 가짜에 없고 진짜에
   있는 것이 반드시 생긴다. 실제로 작업 절차 6개가 전부 **필수 인자** 때문에
   떨어졌는데 단위시험은 통과했다(#223).
4. **틀렸으면 답을 본다.** 무엇이라 답했는지 모르면 못 고친다. 그 하나를 넣자마자
   다음 버그가 바로 나왔다(#233 → #234).
5. **안 쟀으면 안 쟀다고 적는다.** 「넣었다」 와 「재서 좋았다」 는 다른 말이다.
6. **되돌린 것은 까닭과 함께 남긴다.** 다음 사람이 같은 것을 또 시도한다.

## 3. 이미 재 본 것 — 하지 마라

| 해 본 것 | 결과 |
|---|---|
| 역할 붙은 메시지(`user`/`assistant`) | **9/12 → 7/12**, 평균 68→15초. 두 판 재현 |
| 못 찾았을 때 낱말 목록 보여 주기 | **9/12 → 8/12**. 멀쩡하던 문항을 깨뜨렸다 |
| 도구 안 부를 때 「더 찾아라」 밀기 | CIE 실측 52%→48%, 235초→420초 |
| 계약 메시지 목록으로 먼저 묻기 | 상태 타입 2/4 → 0/4 |
| 지침을 앞에서부터 자르기 | 3/4 → 0/4 (핵심 절이 통째로 빠진다) |

**역할 메시지가 왜 나쁜가**: codex·aider 는 도구 결과를 `tool` 역할로 보낸다.
우리는 네이티브 `tool_calls` 를 못 써서 `user` 로 넣는데, 역할이 **진짜로** 붙으면
모델이 그 턴을 「사람이 새로 말을 걸었다」 로 읽고 끝내 버린다.
**반쪽은 안 하느니만 못하다.** 네이티브가 되면 그때 함께 켠다
(`LLM_ROLE_MESSAGES=1`).

#244·#245 는 **아직 배포 안 됐다.** 다음 측정에서 이 둘이 줄어드는지 본다.

**관문이 「무엇이 틀렸나」 만 말하고 「어디를 고치나」 를 빼먹으면 모델은 찾는 데
턴을 쓰고 세 시도를 다 쓴다.** 되먹임을 쓸 때 늘 이걸 본다.

### 에이전트: 틀린 셋은 전부 한 갈래 — 임포트 목록

    find_tools("imports")  → 2개,  list_names 없음   ← 모델이 쓰는 낱말
    find_tools("symbol")   → 22개, list_names 있음

맞는 도구 `list_names` 의 설명은 「external symbol」 이다. **모델이 「imports ≈
external symbols」 를 못 잇는 것**이고, 낱말 목록을 보여 줘 봤지만 안 통했다
(위 표). 동의어를 코드에 박는 것은 그 한 문항에 맞추는 짓이라 **안 고치고 적어 둔다.**

## 6. 함정 — 두 번 밟은 것들

- **`protoAtHead` 는 HEAD 만 읽어야 한다.** 작업 트리로 물러서면 이번에 만든
  파일이 「원래 있던 것」 으로 둔갑해 관문이 조용히 꺼진다(#244).
- **판정을 두 곳에서 하지 마라.** 도구가 통과라 한 것을 관문이 막으면 모델은
  고칠 길이 없다(#205).
- **이름만 알려 주고 인자를 안 주면 못 부른다.** 도구도 절차도 마찬가지다
  (#214 → #223 에서 같은 실수를 두 번).
- **`JAVA_HOME` 이 없으면 Ghidra 가 조용히 안 돈다.** `rea doctor` 는 healthy
  라고 한다 — 스스로 Java 를 찾기 때문이다. `~/.acs/mcp.json` 의 `env` 에 넣는다.
- **큰 것 하나 때문에 작은 것 버리는 규칙은, 가장 쓸모 있는 것이 클 때 해롭다**
  (#236).
